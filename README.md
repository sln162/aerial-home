# Aerial 主页直达

**给 Aerial 兜底的服务：开机黑屏、关机再开或睡醒的第一帧落在极米桌面时，把它请回来。按主页键的「用哪个桌面」弹框归谁收，看首选记录：写了宽记录（`MAIN + HOME`，不带 DEFAULT）指向 Aerial，就由本服务点掉；没有宽记录，就交给 Aerial 自己收（1.97 起）。Aerial 2.0 已把我们的 [#1587](https://github.com/pengchujin/aerial-tv/pull/1587) 收进 main——写了宽记录的那一档，上游不再插手，完全由本服务收框。**

极米投影仪（Android 9 那一代固件）把 Aerial 当桌面用时有两类毛病：

- 按主页键先弹「用哪个桌面」的选择框，卡几秒才回来；
- 开机时首选记录被固件作废，选择框停在初始化画不出来，整屏黑。

第二类上游管不到——黑屏时 Aerial 自己根本没起来，只能由外面兜（Aerial 自己的锁屏兜底 [#1449](https://github.com/pengchujin/aerial-tv/pull/1449) 在极米这台会被挡：它要求「这次绑定一个事件都没收到」，而极米开机自动对焦会先弹一个从不绘制的对话框，一条窗口事件就把条件废掉，所以外面这一层不是多余）。第一类上游自己会收（1.97 起的 [#1523](https://github.com/pengchujin/aerial-tv/pull/1523)：先发返回键关框、再补一次主页键），但只在「没有宽记录」那一档成立；写了宽记录时它关也白关（补的那次主页键又落回同一个框），所以我们在 [#1569](https://github.com/pengchujin/aerial-tv/issues/1569) 里提了折中判断：宽查询答 Aerial 就整段跳过，做成 [#1587](https://github.com/pengchujin/aerial-tv/pull/1587)——已并入 main，随 Aerial 2.0 发布。

## 现在的定位：按记录分工

| 首选记录 | 按主页键时 |
|---|---|
| **写了宽记录**（`MAIN + HOME` 无 DEFAULT，宽查询答 Aerial）：只写宽、双写里宽那条、双写被系统丢掉窄那条之后的形态，都落这一档 | **本服务出手**：框一出现就点掉，0.4 秒量级 |
| **没有宽记录**（两条首选记录都清空，宽查询落到 `ResolverActivity`） | 交给 Aerial 自己收（[#1523](https://github.com/pengchujin/aerial-tv/pull/1523) 那一套，实测量级相同） |
| 任何记录状态 | 开机黑屏、关机再开 / 睡醒落到极米桌面，仍由本服务兜 |

代码里的让位判据是一条，两件事一起看：**Aerial ≥ 1.97 且宽查询不答 Aerial**，才退场；宽查询答 Aerial 时不管 Aerial 装到哪个版本，都归本服务（每次弹框都重算，不缓存一次性结论）。所以 Aerial 2.0 一到，分工就定死：宽记录那一档上游整段跳过（#1587），只由本服务收框；没有宽记录那一档由上游关框，本服务一行不碰。

## 它具体做什么

三条路，全在一个无障碍服务里：

### 1. 开机黑屏

开机后头几分钟（服务绑上后 3 分钟窗口、且开机未满 10 分钟），每 2 秒看一次前台。开机动画收掉（`init.svc.bootanim` 停，或系统置了 `sys.boot_completed`）之后，连续两轮前台都是空的，就把 Aerial 拉起来；Aerial 到过前台一次，这次开机就收工。同一次开机里服务被极米重绑，「刚见过 Aerial」的记号会落盘继承（同一次开机、2 分钟窗口），不会把刚起来的桌面再拉一次。两次动作至少隔 5 秒，一次开机最多救 3 次，救不起来就收手。实测 uptime 69.9 秒救援、73 秒到前台、77 秒画出第一帧。

### 2. 关机再开 / 睡醒

常驻的看门狗（平时 1 秒一轮）不靠猜「睡了多久」，直接问系统要账：`elapsedRealtime`（含深度休眠）减 `uptimeMillis`（不含），差一下子变大（>800 毫秒）就说明真睡过——睡 20 秒也认；另留一条「两轮间隔超过 20 秒」的兜底。醒来时落在极米桌面或整屏黑（连续两轮没画面），就把 Aerial 请回来；屏还没亮就动手，亮屏第一帧就是 Aerial。你已经开起别的 app 就不抢（连着三轮看到别人的 app 就收工，系统界面 `systemui` 不算）。拉这一下之前会先挂一个 1px 的无障碍覆盖窗口（按 HOME 之后应用在后台，直接启动会被系统挡掉），6 秒后自动撤掉。

### 3. 按主页键点框

弹框出现那一瞬（极米的 `com.xgimi.xgimiframeworkui` resolver，或 AOSP 的 `ResolverActivity`）就动手，3 秒冷却防连刷。事件偶尔会漏，看门狗兜着：前台突然变成极米框架窗口、或者前台空但窗口列表里还压着一个框，都按弹框处理（实测 34 次里 2 次走这条路）。

## 点框链怎么走

1. **先判让位**：Aerial ≥ 1.97 且宽查询不答 Aerial → 一行日志退场，其余什么都不做。
2. **找框**：从所有窗口里挑出弹框那个窗口的根节点——就算它被盖住、没有焦点也能拿到，点击直达那个窗口，不看谁在前台。
3. **认 Aerial 行**：行名用系统给的应用标签（跟着系统语言走，Aerial 或极米桌面装包 / 升级、系统换语言都会重读），认不到退回文字「Aerial」。
4. **点行**：点中 Aerial 那一行，「仅此一次」才会变亮；窗口刚起来还不收输入时这一下会落空，隔 200 毫秒重点，最多两次。
5. **点「仅此一次」**：80 毫秒一轮等按钮变亮（最多 16 轮 ≈ 1.3 秒），一亮就点；按钮先认控件 ID（`button_once`，与语言无关），再认几种语言的文字。点完**立刻**把 Aerial 拉起来，抢在弹框自己启动极米桌面之前。
6. **核对**：600 毫秒后看框走没走，没走就重点（最多两次；开机那阵子系统忙，点击会被吞）；之后每 300 毫秒看一次前台，超过 5.6 秒还没到 Aerial 就自己再拉一次；看到你在用别的 app（超过 1.5 秒）就收手不抢。
7. **兜底**：「仅此一次」认不出来，就点「取消」——选候选之前三个按钮里唯一亮着的那个就是它，关掉框、自己再拉一次。绝不按按钮顺序猜哪个是「仅此一次」：有的固件把「始终」排在第一个，猜错就是把首选桌面写错。

实测（极米 H3S，本服务出手那一档）20 连按 20/20：

```
+0~1ms      click row Aerial=true
+106~126ms  click 仅此一次 (round 1)
+13ms       pull: start aerial right after click 仅此一次
+399~448ms  check#1 front=app.orchard.tv
```

事件漏了走看门狗同样 0.5 秒内到站。

## 自我修复

极米在开机和解锁时会改写无障碍列表，把第三方服务剔掉。服务盯着这条设置，被改了 1.5 秒后把自己写回去，顺手把 `accessibility_enabled` 置 1。只写自己、不动别人的服务——别的应用要不要无障碍是用户的授权，不替用户开（发现列表里没有 Aerial 自己的守护时只留一行警告日志）。开机广播（`LOCKED_BOOT_COMPLETED` / `BOOT_COMPLETED`）也会在 3 秒后补一次写入。

## 对机器的影响

不靠定时扫节点树。日常只有两个常驻动作：开机黑屏判据（每 2 秒读一次前台包名，只在前几分钟），和 1 秒一次的看门狗（刚绑上、或刚把自己写回列表后 30 秒内加密到 0.4 秒）。每次只读「当前窗口属于哪个包」，不遍历节点树、不起子进程；节点扫描只发生在弹框出现的那一下。

实测（极米 H3S，总内存 3.5 GB）：`top` 和 `dumpsys cpuinfo` 常显 `0.0%`；装完头 7 分钟累计 CPU 只有 3 秒；内存 PSS 约 16 MB，占 0.4%。

| | 这个守护 | Aerial 自己 |
|---|---|---|
| CPU（亮屏待机） | 0.45% 单核 | 10.3% 单核 |
| 内存 PSS | 16 MB | 166 MB |

也就是它只占 Aerial 的 1/23 CPU、1/10 内存。每秒一次看门狗 ≈ 4.5 毫秒 CPU，会打断 CPU 空闲态（对插电的投影影响很小）；设备真睡着时 Handler 被冻住，不再消耗，待机功耗不受影响。

| [#1587](https://github.com/pengchujin/aerial-tv/pull/1587) 宽查询答 Aerial 时整段跳过 | 已并入 main，随 Aerial 2.0 发布 | 宽记录那一档完全交给本服务，上游不再插手 |
| [#1534](https://github.com/pengchujin/aerial-tv/pull/1534) 被固件删掉 1.5 秒后补回 | 已并入 main（`c21c8f3`） | 与本服务同源的问题，交给上游处理 |
| [#1449](https://github.com/pengchujin/aerial-tv/pull/1449) 锁屏期兜一次 | 已并入 main（`82a497a`） | 上层兜底；极米这台被对焦框挡住，本服务补这一块 |
| [#1474](https://github.com/pengchujin/aerial-tv/issues/1474) | Issue，讨论中 | 上游不背书第三方无障碍服务，所以这类活留在本仓库 |

两者各管一档，不需要为装本服务去停用上游的守护；Aerial 2.0 起 #1587 已生效，分裂态（只写宽 / 双写丢了窄那条）只由本服务动作，上游不再同时插手。

## 支持范围

判据不是机型，是**系统弹的是不是个 resolver 选择框**（极米这一代是 `com.xgimi.xgimiframeworkui...resolver.ResolverActivity`，AOSP 是 `android/com.android.internal.app.ResolverActivity`）：只要走的是它，跟机型无关。

- **Android 9 极米：实测可用**（H3S 上跑了 180 多次按主页键、多次重启、多次关机唤醒）
- **Android 11 及更新的极米：未实测**。机制一样（resolver + 无障碍点节点），预计可用；认不出来时退化成不动手，不会乱点别的窗口
- 其他品牌 / AOSP：只要弹的是系统 resolver 就走同一条路径，未实测
- 出场与否先看 Aerial 版本（≥1.97 才谈得上让位），再看宽记录答不答 Aerial；上游 2.0 已合并 #1587，宽记录这一档只由本服务管

## 装法

1. 从 [Releases](https://github.com/sln162/aerial-home/releases) 下 APK，覆盖安装失败就先卸载旧的（调试签名）
2. adb 三条：

```
pm grant com.sln162.aerialhome android.permission.WRITE_SECURE_SETTINGS
settings put secure enabled_accessibility_services \
  'com.xgimi.duertts/.MonitorService:app.orchard.tv/.guard.HomeGuardService:com.sln162.aerialhome/com.sln162.aerialhome.BootA11yService'
settings put secure accessibility_enabled 1
```

3. 打开一次应用，「运行状态」显示绿色「正常」就成了

`pm grant` 不是可选项：极米在解锁那一刻会重写无障碍列表，把第三方服务剔掉，没有这个权限服务写不回去。早期版本还要求过 `appops` 的悬浮窗授权，现在的代码用无障碍自带窗口，不需要了。

## 怎么更新

覆盖安装就行，不用卸载、不用重新授权：

```
adb install -r AerialHome-<新版本>.apk
```

装完打开应用，看「运行状态」是不是绿色「正常」。不是的话，把无障碍开关关一下再开——极米解锁时会重写无障碍列表，服务自己会补回去，补不回来才需要手动开一次。
日志里有 `bound, uptime=` 一行，就说明服务已经被系统绑上了。

## 界面看什么

| 区块 | 内容 |
|---|---|
| 运行状态 | 正常 / 未运行 / 权限不全，各带一句怎么办 |
| 上次救黑屏 | 最近一次兜底的时间；没发生就是「还没发生过」，下面是累计次数 |
| 主页规则 | 开机查询（HOME）、主页键查询（HOME + DEFAULT）各自解析到谁，两处都是 ResolverActivity 就写「没设置双 home」 |
| 按主页键 | 累计次数；最近 8 次带时间、`+Nms`、怎么处理的（「点仅此一次」「看门狗补」「取消兜底」） |
| 最近日志 | 日志末 10 行，长包名压成「极米弹框」「三项无障碍列表」 |

遥控器左右键在「墨绿 / 米白 / 深蓝」之间换配色，自动保存。

## 它不做什么

- **不写 HOME 首选记录，不点「始终」**。这个弹框里「始终」写进的是默认选中那一行（极米桌面）；点候选行、`ACTION_SELECT` 都不是干净的做法
- **不超过上游**：Aerial ≥ 1.97 且宽查询不答 Aerial 时一行不碰，弹框留给 Aerial 自己关
- **不发返回键抢活**：返回键永远发给当前焦点窗口，在第三方 app 里按主页键时会落到那个 app 身上（记录清空那档由上游自己处理）
- **不冻结、不禁用极米自带桌面**，不动系统组件
- **认不出按钮就不猜**。宁可点「取消」把框关掉、自己再拉一次，也不按位置或顺序赌哪个是「仅此一次」

## 局限

- 只在 Android 9 极米固件上跑过，更高版本未实测
- 选「仅此一次」之后弹框会启动默认那一行（极米桌面），我们紧接着自己拉起 Aerial 盖掉；这一步靠无障碍服务的后台启动豁免
- 个别时候到站 0.6 秒；开机刚起来那一阵系统忙着重写无障碍列表，会到 1 秒出头
- 弹框被 Aerial 完整盖住后节点就从 `getWindows()` 里消失，所以动作放在事件里执行

## 日志

```
adb shell run-as com.sln162.aerialhome cat /data/user_de/0/com.sln162.aerialhome/files/rescue.log
```

每行「墙钟 + `u=` 开机内时钟」，跨开机的时间线靠 `u=` 对齐；超过 512 KB 轮转成 `rescue.log.1`（只留一代）。同内容还镜像到外部目录的 `rescue-ext.log`——这机器 logd 是停的，logcat 读不到，adb 只能 tail 这里。
